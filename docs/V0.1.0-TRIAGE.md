## 1. Decisions needed before code starts

### 1a. "Typical period duration" is the wrong variable

Period duration — how many days you bleed — has no effect on the due date. Naegele's rule counts
from the *first day* of the last period; a 3-day period and a 7-day period from the same start date
give the same due date. Asking for it and then adjusting the count would produce a wrong date.

The variable that does move the due date is **cycle length**. Ovulation sits roughly 14 days before
the *next* period, not 14 days after the last one, so a long cycle pushes conception (and the due
date) later:

```
EDD = LMP + 280 + (cycleLength − 28)
```

A 35-day cycle moves the due date a week later; a 24-day cycle moves it four days earlier. This is
the standard adjusted-Naegele / Parikh correction, and it is what LMP-based calculators that ask a
second question actually ask for.

**Assumed unless you say otherwise:** ask for cycle length (21–45 days, default 28), LMP mode only,
apply the formula above. Say the word if you meant something else by "period duration."

This is the item with the largest blast radius in the codebase, which is why it is mine and not
delegated:

| Touches | Why |
|---|---|
| `src/lib/gestation.ts` | `toLmpEquivalent`, `convertInputDate`, `dueDateFrom` all assume 280 flat |
| `docs/decisions/ADR-002-*.md` | the constant is an accepted decision; it needs an amendment |
| `src/lib/storage.ts` | a third persisted field, plus a schema version bump for saved state |
| share links (`?m=&d=`) | a shared LMP link now under-specifies the pregnancy — see 1b |
| `src/lib/laborProbability.ts` | the model is calibrated in gestational days from LMP; the offset has to be applied before, not after |

### 1b. Share links and cycle length

A `?m=lmp&d=…` link sent to a partner would silently reconstruct a different due date than the
sender sees. Options: add `&c=32` to the link (leaks a little more about the sender), or convert the
link to due-date mode on copy so the recipient gets the same due date with no extra field. I lean to
the second — it shares strictly less personal data, which is consistent with ADR-006. Your call.

### 1c. What replaces "days to go" on the present week

The ask is to swap the "days to go" text for "6 weeks ahead" when browsing. Unstated: what shows on
the *current* week, where "0 weeks ahead" is meaningless. **Assumed:** the present week keeps
"119 days to go"; the offset text only appears when you have navigated away.

## 2. The sequencing constraint that dictates everything

`tests/e2e/__screenshots__` holds 14 per-skin pixel baselines, and CI gates on them. Every UI change
in this list invalidates all 14. Baselines can only be regenerated on the GitHub runner (README,
"Update the skin screenshots"), and two branches that each regenerate them will conflict on merge in
a way git cannot resolve.

**Therefore:** all UI packages land on one integration branch and the baselines are regenerated
**once**, at the end, before the PR merges. Do not regenerate per package.

Corollary: parallelism here is bounded by file collisions, not by how many agents I can start. The
real parallel win is the fact-check, which touches no code at all.

substitute for it. `reviewed: true` stays a human act.

Not haiku. Fact-checking is exactly the task where a cheap model confabulates a confirmation.

### P6 — Font consistency audit · **sonnet, report first** · read-only

No literal font families exist outside `tokens.css` / `fonts.css` — the stylelint rule already
prevents that. So the question is not whether fonts are hardcoded, it is whether the *right token* is
used in each place, and there are real candidates: `.card__week` is body-italic, `.big small` is
body inside a display heading, `.preview__value` is display at 25px while `.dim b` is mono at 14px
for the same class of number. Audit produces a table of every text style with its token, size, and
weight; I decide which are inconsistencies and which are intentional; the patch follows.

Cheapest task on the list. Haiku could produce the table; sonnet is a few cents more and can tell a
deliberate contrast from a slip, so sonnet.
