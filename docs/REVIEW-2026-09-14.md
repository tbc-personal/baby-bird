# Nestling review — 2026-09-14

Reviewed at `5029c25` on `main`. Everything green: `lint`, `typecheck`,
`validate-data`, 671 unit tests. Build succeeds. The app was driven in headless
Chromium at 420×900 (light, dark, offline) — no console errors, no failed
requests, no 4xx.

Findings below are ordered by how much they cost, not by where they live.

---

## 1. The Macaulay embed path is dead and still shipping

This is the single biggest item. ADR-003 says the embed route was abandoned on
2026-09-08 and Wikimedia Commons replaced it. The data agrees: **zero rows carry
an `mlAssetId`; 36 of 42 rows are `provider: "commons"`.** But the code for the
abandoned route is all still here and still in the production bundle:

| File                               | Lines       | Status                                                                            |
| ---------------------------------- | ----------- | --------------------------------------------------------------------------------- |
| `src/components/MacaulayEmbed.tsx` | 179         | `MacaulayEmbed` unreachable; `PhotoFrame` and `PhotoComing` still live            |
| `src/components/macaulay.ts`       | 40          | `macaulayEmbedUrl` unreachable; `macaulayAssetUrl` only called from a dead branch |
| `src/useOnline.ts`                 | 30          | only consumer is `MacaulayEmbed`                                                  |
| `src/components/OfflineGoose.tsx`  | ~55         | only reachable through `MacaulayEmbed`                                            |
| `tests/unit/images.test.tsx`       | ~150 of 226 | exercises the dead component                                                      |

Plus dead branches in `ComparisonCard.renderPhoto`, `ImageCredit.creditContent`,
`schema.ts` (`mlAssetId`, `fallbackMlAssetId`, `embedUrl`), and
`scripts/check-links.ts`.

I confirmed offline in a browser: the app reloads fully offline with the photo
intact, because every image is a local file now. The offline goose cannot be
reached.

Two structural consequences worth noting:

- `PhotoFrame` is the shared frame for _every_ photo state, and it lives inside
  `MacaulayEmbed.tsx`. So `CommonsImage.tsx` imports its frame from a file named
  after the route that was deleted. That is confusing to read.
- `PhotoComing` is still genuinely needed — 4 weeks have no photo (below).

## 2. Genuinely dead exports

Confirmed with a repo-wide sweep; no references anywhere in `src`, `tests`, or
`scripts`:

- `LENGTH_CONVENTION` — `src/data/comparisons.ts:13`
- `APP_NAME` — `src/lib/gestation.ts:11`
- `CONCEPTION_TO_DUE_DAYS` — `src/lib/gestation.ts:16`
- `AA_NORMAL_TEXT`, `AA_LARGE_TEXT` — `src/lib/contrast.ts:53-54`
- `formatInputDate` — `src/lib/dates.ts:35`. `gestation.ts`'s `formatIsoDate`
  does the identical job and is the one Setup actually calls. Two
  implementations of `yyyy-MM-dd`.

Two more are exercised only by their own tests, never by the app:

- `weightDetail` (`measures.ts:61`) — `ComparisonCard.tsx:80-85` inlines the
  same ternary instead of calling it.
- `comparisonPhrase` (`measures.ts:92`) — `ComparisonCard` splits the article
  from the noun for layout reasons, so this can never be used.

Both have passing tests. The tests are testing a second implementation of
something the app does elsewhere, which is the failure mode where you change the
real code and the suite stays green.

`FIT_RESIDUALS` is also test-only, but that one is legitimate — it is the fitted
constants being pinned.

## 3. Bugs a user can hit

**3a. "The table runs from week 2 to week 42."** — `Today.tsx:58` and
`Today.tsx:229`. The table runs from week 3. `FIRST_COMPARISON_WEEK = 3` is
imported three lines above the first of these. Reproduced at `#/week/99`.

**3b. The measure chart's first axis label is wrong and sits outside the plot.**
`MeasureChart.tsx:19` — `AXIS_WEEKS = [2, 12, 22, 32, 42]`, but the x scale is
anchored on `FIRST_COMPARISON_WEEK` (3). `x(2)` computes to roughly 6px left of
the axis origin, so "2w" is drawn floating off the left end of a chart whose
data starts at week 3. Visible in the screenshot.

**3c. The trimester pill does not follow the browsed week.** Standing at week 25
and navigating to `#/week/3`, the header still reads **"Second trimester"** over
a poppy seed. Verified in the browser. The progress bar has the same problem,
though a bar that means "how far along you are" is defensible on its own; the
pill is not, because it sits directly above a card for a different week.

**3d. Six consecutive weeks all read "0.04 oz".** Weeks 3–8 share the same
weight value. Weeks 3 and 4 are flagged `weightIsUpperBound`, so their cards say
"weight, under 0.04 oz"; weeks 5–8 are not flagged, so theirs say plain
"weight". Same number, two different meanings, no visible difference. On the
Timeline there is no qualifier at all, so the list reads as though a millet
seed, a sunflower seed, a House Wren egg and a Barn Swallow egg all weigh
exactly the same. This looks like a data question rather than a code one: either
0.04 is the source table's floor for all six, or it isn't.

**3e. Four weeks still show "Photo coming".** Weeks 7 (House Wren), 9 (Wood
Thrush), 12 (Great Blue Heron), 13 (Bald Eagle) — all egg weeks.
`validate-data` reports them as warnings. ADR-003's header claims Commons is now
"the route for all 42 weeks", which is not yet true.

**3f. The labor panel bottoms out at 37 weeks.** ADR-005 documents this
honestly, but the size is worth restating because it is the app's most
prominent number in the weeks people watch hardest:

| Week      | "chance labor starts in the next 7 days" |
| --------- | ---------------------------------------- |
| 34w0d     | 1.56%                                    |
| 35w0d     | 1.58%                                    |
| 36w0d     | 1.28%                                    |
| **37w0d** | **0.48% → displays as "under 1%"**       |
| 38w0d     | 5.55%                                    |

The underlying density falls 18-fold in one day at day 259 (37w0d), where the
truncated preterm component stops dead and the term component has not started.
A user at 37 weeks is told they are less likely to go into labor this week than
they were at 34. ADR-005 names two ways out and neither is expensive; option 2
(start the panel at 37 weeks) is a one-constant change.

**3g. A failed clipboard copy says nothing.** `ShareLink.tsx:24-31` — `copy()`
returns `false` on refusal and the status line just stays blank. The user taps
and nothing happens.

**3h. "the first two weeks are before conception."** — `Today.tsx:97`. Three
weeks now have no card, not two, since the table starts at week 3.

## 4. Copy

**4a. The About page still explains Macaulay Library licensing.** The
"Non-commercial" section says "Macaulay Library media may be embedded for
non-commercial purposes only." There is no Macaulay media in the app. Cornell is
not mentioned anywhere else a user can see. The constraint that actually applies
now is the CC licence on each Commons photo, which is already handled by the
credit disclosure.

**4b. "(ADR-002)" is in user-facing copy.** `AboutContent.tsx:51` — "a cycle
longer than 28 days means later ovulation and a later due date (ADR-002)". An
internal document reference leaked into the product.

**4c. Roadmap noise in About.** "A 'chance of continuing' panel for early
pregnancy is planned but not built. It is deferred to a later version and will
be opt-in and permanently hideable, coming later." A user does not need to know
about an unbuilt feature, and "deferred to a later version … coming later" says
it twice.

**4d. "Show me my nestling."** The submit button. Everything else in the app is
plain and direct; this is the one place it goes twee, and it lands right at the
moment a person is handing over a pregnancy date. Also inconsistent with the
tagline directly above it, which is plain.

**4e. The labor screen's mono stat line.** `Labor.tsx:88` — "5% have started
labor by this point." set in monospace after two paragraphs of prose. It reads
like debug output, and it duplicates what the chart's own `aria-label` already
says.

**4f. "weight (23.36 oz)".** Two decimal places. Every other number in the app
is rounded to something a person would say.

This is the largest category by volume.

wrong: no asset IDs (true, but they are no longer wanted), no seed photos (there
are four), the embed `src` unverified (the route is gone), "all 123 facts are
`reviewed: false`" (there are 120, and 96 are reviewed), and the labor dip
(still true). The status paragraph above it says the same things again. The
Sources section still credits "Macaulay Library … (embedded, non-commercial)".

**`data/comparisons.json` `$comment`** — "facts … are all reviewed:false" and
"image is still empty: the build session had no network access". Both false.
This is the first thing anyone opening the data file reads.

**`docs/CURATION.md`** — contradicts itself within one file. A 2026-09-08
update in the middle records that Commons replaced Macaulay and the fact-check
ran; below it, §A still opens with a 36-row table of Macaulay search URLs to
work through, and §B still says "**123 facts … All 123 are `reviewed: false`.

since changed — the tagline is now "The pregnancy tracking app for bird lovers",
not "Your baby's size, week by week…", and the button is "Show me my nestling",
not "Start counting". §A also still discusses the week 3 grit photo; week 3 is

**ADRs:**

- ADR-003 header claims Commons covers "all 42 weeks" (4 weeks have no photo);

## Proposed plan

Ordered so nothing blocks on a decision that hasn't been made.

### Phase 1 — mechanical, no judgment (delegate to Sonnet)

Four independent tasks, parallel-safe, each verifiable by the existing suite.

1. **Delete the Macaulay path.** Remove `MacaulayEmbed`, `macaulay.ts`,
   `useOnline.ts`, `OfflineGoose.tsx`, `goose-offline.svg`, the `macaulay`
   branches in `ComparisonCard` and `ImageCredit`, the `mlAssetId` /
   `fallbackMlAssetId` / `embedUrl` schema fields and their data keys, and the
   Macaulay checks in `check-links.ts`. Move `PhotoFrame` and `PhotoComing` into
   a new `PhotoFrame.tsx`. Prune `images.test.tsx` to the surviving components.
   Gate: full suite green, `validate-data` clean, offline reload still shows a
   photo.
2. **Remove the six dead exports and fold the two test-only duplicates.** Point
   `ComparisonCard` at `weightDetail` instead of its inline ternary, delete
   `comparisonPhrase`, delete `formatInputDate` in favour of `formatIsoDate`.
3. **Fix the five off-by-one bugs**: 3a (two strings), 3b (`AXIS_WEEKS`), 3h,
   plus the "Weeks 2–42" comments. Add a test that the empty-state copy matches
   `FIRST_COMPARISON_WEEK` so it can't drift again.
4. **Documentation sweep** against the current code and data: README known-gaps
   table and status, the `$comment` in `comparisons.json`, RUNNING-LOCALLY's
   "what you should see", the five ADR lines listed above, PLAN §2/§3/§6, the
   `survey-commons.ts` and `MeasureChart.tsx` comments, `.gitignore`. Per
   CLAUDE.md, each ADR edit records _why_ the decision changed rather than
   quietly overwriting it.

Each of these is a closed question with a checkable answer, which is what makes
them safe to hand off. I'd review every diff before it lands — particularly (1),
because "unused" and "unreferenced" are not the same thing in a codebase with
dynamic branches.

### Phase 2 — mine, because they need judgment

5. **Rewrite `docs/CURATION.md`.** This one is not a sweep. The file has three
   layers of history stacked on each other and the right output is probably a
   short "what is still open" doc plus the historical passes moved to
   `docs/research/`. That is a structural call about how the repo remembers
   things, and CLAUDE.md is explicit that the reasoning has to survive.
6. **The 37-week labor dip (3f).** Both of ADR-005's exits are cheap; choosing
   between them is a product decision about whether the panel's job is to be
   calibrated or to be usable in the weeks people check it. Needs your call
   (below).
7. **The trimester pill (3c).** Three defensible behaviours: follow the browsed
   week, hide the pill while browsing, or label it "today's trimester". I'd pick
   follow-the-week and leave the bar alone, but it's a design call.
8. **Copy pass (4a–4f).** Per your standing preference I won't write replacement
   copy into the product and call it done — I'd propose each line, flag it as
   mine, and let you take the voice pass. 4a and 4b are the two I'd treat as
   outright bugs rather than taste.

### Phase 3 — content, needs you or a decision from you

9. **Four missing egg photos (3e).** `npm run survey-commons` plus
   `crop-preview` already exist for this; a Sonnet agent can shortlist
   candidates, but picking a photo is a judgment call and the crop has bitten
   this repo before.
10. **24 unreviewed facts.** `mark-reviewed.ts` deliberately refuses to flip the
    flag, which is right. Either you do the pass or the release gate stops
    claiming zero is required.
11. **The weeks 3–8 weight floor (3d).** A data question I can't answer from the
    repo.

### What I would not touch

`docs/V0.1.0-TRIAGE.md` and `prompts/opus-build-prompt.md` are dated records of
a past session. They should stay as they are; the fix is that the README's
repository map should describe them as history, which it already half does.
